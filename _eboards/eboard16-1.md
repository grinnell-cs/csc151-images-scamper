### Administrative questions

Review
------

* Goal of course: Learn how to express computational solutions to problems
* We're using an artificial language (Scheme/Scamper) to communicate with
  the computer.
    * Syntax - how you write things. (Lots of parens.)
    * Vocabulary - mostly names of functions.
    * Semantics - how we assign meaning to things.
* We need to be precise in the way we write in this language.
* We need to know the vocabulary well.
* Key to writing computational solutions: expressions and functions
  (also some other things, like definitions)
* There are two kinds of basic expressions in Scheme
    * Basic Values: 4, "hello", #\x
    * Compound expressions: `(function arg1 arg2)`
* About parentheses
    * Can we use parentheses to group in Scheme? No. Parentheses almost
      always signify "This is a function call/compound expression."
    * There are a few cases in which parentheses do not signify "this is
      a function call"
        * With `(define NAME EXPRESSION)` - we're not necessarily computing
          anything, we're just assigning a name to a value for convenience.
        * We also use parens around lambdas and around the parameters for
          lambdas.
* About functions
    * Are there places functions can appear other than immediately after
      an open parentheses? Yes! They can appear without parentheses as
      arguments to `l-s`, `r-s`, `map`, `apply`, ... [Wednesday/Friday]
* A value is something that cannot be simplified anymore.  An argument may
  be a value or it may be an expression that we use to compute a value.
  `(substring (string-append "hello" "world") (+ x 2) (+ x 5))`
* We need differents kinds of values to compute with. We use the term "type"
  for "kind of value". We've encountered a bunch of types so far in 151.
    * Numbers, including integers and real numbers
    * Characters - The building blocks of language (or at least strings)
    * Strings - Sequences of characters. Text to compute with.
    * Booleans - True, False, and nothing in between, used for maknig decisions
    * RGB colors - Ways to add and manipulate colors in image-based programs
    * HSV colors - Another way to play with colors
    * Lists - Sequences of any type of value
    * Shapes - Things we draw (or the computer draws)
    * Images/Canvases - Things with individual pixels
* When we learn a new type, we should ask ourselves some questions:
    * Why do we have the type / how will we use it? For strings: Work with text
    * How do we write the basic values in the type? For strings: With quotation marks around them.
    * How do we make values in the type? For strings: 
        * `(integer->string number)`
        * `(list->string list-of-characters)`
        * `(make-string count char)`
        * `(string char1 char2 char3 ...)`
    * How does Scamper show them to us? For strings: With quotations marks around them.
    * What can we do with them? For strings:
        * `(substring str pos)` - Extract the portion of the string starting
          at charcter `pos`.
        * `(substring str pos1 pos2)` - Extract the portion of the string starting at `pos1` (inclusive) and ending at `pos2` (exclusive).
        * `(string-append str1 str2 ...)` - Combine the strings together into a single string.
        * `(string-split str splitter)` - Splits the string whenever it sees splitter. Returns a list of strings.
* As we noted earlier, we can name things with define statements
    * `(define NAME EXPRESSION)`
    * Why do I call them "define statements" rather than "define expressions"?
        * Most expressions do not affect the rest of the program.
        * We can't put `define` statements inside an expression.
    * We use expressions and statements differently. Statements tend to
      go by themselves, expressions can be nested.
    * Note that you get only ONE expression after the name.
    * Meaning of define statement: Evaluate the expression; thereafter,
      whenever you see the name, you substitute the value of the expression.
* Semantics: How we evaluate expressions. `(+ (* 2 3) (- 5 x))`
    * If there any variables defined by prior `define` statements, substitute
      those in.
    * Evaluate all the arguments to each function before applying the function
        * We usually work left to right.

```
(define c 3)
(define d 4)

    (+ (* c c) (- d (+ c d)))
--> (+ (* 3 3) (- 4 (+ 3 4)))
--> (+ 9 (- 4 (+ 3 4)))
--> (+ 9 (- 4 7))
--> (+ 9 -3)
--> 6
```

Note: Our model of how to evaluate expressions corresponds directly to
how we trace evaluation.

```
(define x "Hello")

    (string-append "[" (string-upcase x) (make-string 3 #\.) (substring x 1) "]")
--> (string-append "[" (string-upcase "Hello") (make-string 3 #\.) (substring "Hello" 1) "]")
--> (string-append "[" "HELLO" (make-string 3 #\.) (substring "Hello" 1) "]")
--> (string-append "[" "HELLO" "..." (substring "Hello" 1) "]")
--> (string-append "[" "HELLO" "..." "ello" "]")
--> "[HELLO...ello]"
```

Functions
---------

* What is a function? Something that takes inputs, does some computation, and produces an output.
    * We often think of functions as generalizations of expressions we've written to accomplish something.
* I might have written `(string-append "[" (string-upcase "sam") "]")` and I'd like to do the "uppercase and surround by brackets" for any string, not just "sam".
* I might have written `(+ 1 (* 2 sams-grade))`
* In Scheme, we have one basic way to define functions (and lots of alternatives).

```
(define NAME
  (lambda (PARAMETERS)
    EXPRESSION))
```

```
(define scale-grade
  (lambda (grade)
    (+ 1 (* 2 grade))))
```

* Semantics of function calls: When you call a function, you substitute
  the inputs/arguments for the parameter.

```
(scale-grade 5) -> (+ 1 (* 2 5)) -> (+ 1 10) -> 11
(scale-grade 6) -> (+ 1 (* 2 6)) -> (+ 1 12) -> 13
    (scale-grade (scale-grade 2)) 
--> (scale-grade (+ 1 (* 2 2)))
--> (scale-grade (+ 1 4))
--> (scale-grade 5)
--> (+ 1 (* 2 5))
--> (+ 1 10)
--> 11
```

When we trace, we're just precisely thinking through how the computer
determines the result of an expression.
    * If there any variables defined by prior `define` statements, substitute
      those in.
    * Evaluate all the arguments to each function before applying the function
        * We usually work left to right.
    * Semantics of function calls: When you call a function, you substitute
      the inputs/arguments for the parameter.

Important points from today:

* Parentheses are important. If you use an open paren (other than in a
  define or lambda), follow it by a function.
* If you want to use a function, you'll usually put it immediately after
  an open paren. (Exceptions: cut, l-s, r-s, map, ...)
* Tracing is just an attempt to understand how the computer evaluates
  expressions.
* To succeed in 151, you need to know the vocabulary for diff types.
